## Enums

### `public.app_role`

| Value | Typical link column on `user_roles` |
|-------|-------------------------------------|
| `admin` | none (full access via RLS) |
| `landlord` | `landlord_id` → `Landlords` |
| `tenant` | `tenant_id` → `Tenants` |
| `maintenance` | `staff_id` → `Staff` (staff / maintenance workers) |

## Tables (public)

All domain tables below have **RLS enabled**. IDs are `bigint` identity (`GENERATED BY DEFAULT AS IDENTITY`) unless noted. Most domain tables include `is_test_data boolean NOT NULL DEFAULT false`.

### `user_roles`

| Column | Type | Notes |
|--------|------|-------|
| `user_id` | uuid PK | → `auth.users` |
| `role` | `app_role` NOT NULL | |
| `landlord_id` | bigint nullable | |
| `tenant_id` | bigint nullable | |
| `staff_id` | bigint nullable | |
| `created_at` | timestamptz | |
| `account_status` | text | `pending \| approved \| rejected \| suspended`; default `pending`. Bootstrap admins set to `approved`. App gate + SQL helpers require `approved`. |

Policies: select own row (`authenticated`); select all for `supabase_auth_admin` (hook).  
**Phase 2:** no client UPDATE policies — admins change status/role via SECURITY DEFINER RPCs `list_user_accounts_for_admin`, `set_account_status`, `admin_set_user_role` (email from `auth.users`).

### `Landlords`

Key columns: `id`, `source_id`, `first_name`, `last_name`, `company_name`, `email` NOT NULL, `mobile_phone`, `preferred_contact`, `notes`, `is_test_data`, `created_at`.

**RLS (pre-Phase 1):** select for admin / self landlord / tenant-of-landlord / staff-who-sees-landlord.  
**Phase 1 adds:** admin insert/update/delete policies.  
**WS-A (`20261114010000`):** `authenticated` table GRANT INSERT/UPDATE/DELETE (+ identity sequence USAGE/SELECT) — policies existed but privileges were still SELECT-only on live/emulator baseline. Same grant for `Properties`, `Units`, `Tenants`.

### `Properties`

Key columns: `property_name`, `street_address` NOT NULL, `city`/`state`/`zip` NOT NULL, `property_type` NOT NULL, **`landlord_id` NOT NULL**, `management_status`, `occupancy_status`, `management_end_date`, `year_built`, `color`, `notes`, `source_id`, `is_test_data`.

**RLS:** select for admin / owning landlord / tenant’s property / staff assigned via maintenance.  
**Phase 1 added:** admin write; landlord update/insert for own `landlord_id`.  
**LGA-19:** landlord insert/update policies **dropped** — landlords are **read-only** on Properties (admin write only).

### `Units`

Key columns: `property_id` NOT NULL, `unit_label` NOT NULL, `bedrooms`, `bathrooms`, `status`, `management_status`, `occupancy_status`, `readiness_status`, `currently_being_marketed`, `sqft`, `market_rent`, dates, `notes`, `source_id`.

### `Tenants`

Key columns: `first_name`, `last_name`, `email` NOT NULL, `mobile_phone`, **`unit_id`** (Phase 1 migration: **nullable** so portfolio tenants can exist before lease assignment; was NOT NULL), `primary_on_lease`, `invite_to_app`, demographics, `notes`, `source_id`.

### `Staff`

Key columns: `first_name`, `last_name`, `email` NOT NULL, `job_title`, `gets_request_alerts` NOT NULL, `is_test_data`.

### `Leases` / `LeaseTenants`

Leases: `unit_id`, `primary_tenant_id`, `start_date`, `end_date`, `monthly_rent`, `deposit`, `rent_due_day`, `late_fee`, `status` (default `active`), `notes`, `is_test_data`.  
LeaseTenants: composite PK `(lease_id, tenant_id)`.

**Pre-Phase 1:** RLS on, **no policies** (advisor).  
**Phase 1:** admin/staff/landlord-scoped policies via `private.*` helpers.

### `RentCharges` / `Payments`

Charges: `lease_id`, `period` (`YYYY-MM`), `due_date`, `amount`, `amount_paid`, `status`, `notes`.  
Payments: `charge_id`, `paid_at`, `amount`, `method`, `reference`, `notes`.

Same advisor gap → Phase 1 policies.  
**Phase 1.5:** `FORCE ROW LEVEL SECURITY`; portal mutates via RPCs `public.record_payment` / `public.delete_payment` (admin-only; `amount_paid`/`status` from `SUM(Payments)`). Authenticated Payment INSERT/UPDATE/DELETE policies dropped — use RPCs only (SELECT kept for history).

### `Vendors`

`name`, `category`, `phone`, `email`, `notes`, `color`, `is_test_data`. Phase 1: admin CRUD policies.  
**Phase 1.5:** `vendors_select` narrowed to `private.is_staff_or_admin()` (landlords no longer SELECT all vendors); `FORCE ROW LEVEL SECURITY`.

### `Settings`

Key/value: `key` PK, `value`, `updated_at`. Phase 1: admin (and optionally maintenance staff) read/write. **Phase 1.5:** `FORCE ROW LEVEL SECURITY`.

### `Applications`

Rental applicants (not account approval). Do not confuse with `user_roles.account_status`.

Key columns: `unit_id`, `first_name`, `last_name`, `email`, `phone`, `monthly_income`, `employer`, `desired_move_in`, `status` (default `new`: `new|screening|approved|declined|withdrawn`), `notes`, `is_test_data`.

**Phase 2 RLS:** staff/admin SELECT/INSERT/UPDATE; admin DELETE; `FORCE ROW LEVEL SECURITY`.  
**LGA-19:** narrowed to **admin-only** SELECT/INSERT/UPDATE/DELETE (maintenance staff must not read applicant income / PII).

### `MaintenanceRequests` (+ Photos, Comments, StatusHistory)

Staff/tenant maintenance model. Status CHECK (live): `Open | Scheduled | In Progress | On Hold | Closed` (default `Open`). Priority CHECK: `Low | Normal | High | Urgent` (default `Normal`). Category CHECK: `Plumbing | Electrical | Heating / AC | Appliance | Pest control | Locks / keys / doors | Windows | Roof / leaks | Mold / water damage | Exterior / yard | General repair | Other`. Has `request_number` (trigger `private.assign_request_number`), `permission_to_enter`, `property_id`, `vendor_id`, `cost`, `notes`, assignment/scheduling fields. Companion CHECKs require staff+date for Scheduled, staff+started_at for In Progress, hold_reason+follow-up for On Hold, closed_at+resolution_notes for Closed.

**Live ACL baseline** (pre-repo Oct migrations + Phase 3 tighten; full predicate table in [`docs/ops/live-maintenance-acl-baseline.md`](./ops/live-maintenance-acl-baseline.md)):

- SELECT: admin / submitting tenant / assigned staff / landlord owns unit (`maintenance_requests_select`)
- UPDATE: USING `private.can_update_maintenance_request(id)`; WITH CHECK on the NEW row — admin or assigned maintenance only (`maintenance_requests_update`, LGA-19)
- DELETE: admin (`maintenance_requests_admin_delete`); **WS-A** adds `GRANT DELETE` to `authenticated` (policy existed; privilege missing)
- Comments SELECT: `can_select_maintenance_request` + visibility rules (`maintenance_comments_select`)
- Photos / comments mutate via `can_upload_maintenance_photo` / `can_update_maintenance_request` (and tenant comment path)

**Phase 3:** `MaintenanceRequestStatusHistory` (append-only via trigger). Accept & schedule (`Scheduled` / `scheduled_for`) is **admin-only** (`protect_maintenance_request`). Comments: `visibility` = `tenant_visible` \| `internal` (tenants only see `tenant_visible`).  
**LGA-19:** landlord removed from UPDATE + `private.can_update_maintenance_request` (read-only WOs — cannot close or edit; comment/photo writes via that helper also denied).

### `PropertyDocuments`

Property (and optional unit) file metadata. Visibility CHECK: `tenant | staff | landlord` (default `staff`). Path shape `{property_id}/{filename}`.

**Phase 5:** Admin-only visibility mark (trigger + INSERT/UPDATE policies). Hierarchical SELECT via `private.can_select_property_document`. Staff/admin manage via `private.can_manage_property_documents`. FORCE RLS. Storage bucket `property-documents` (private, 20 MB). `unit_id` ON DELETE CASCADE (unit-scoped docs must not widen ACL via SET NULL).

### `inquiries`

Website contact form (`uuid` id). RLS on, **no policies** — intentional so only service role can write. **Do not break.**

## Advisor gaps (security linter)

**Before Phase 1 migration:** RLS enabled with **no policies** on:

- `Applications`, `Leases`, `LeaseTenants`, `RentCharges`, `Payments`, `Vendors`, `Settings`, `inquiries`

**Phase 1 addresses:** Leases, LeaseTenants, RentCharges, Payments, Vendors, Settings (+ admin write policies on core portfolio tables).  
**Phase 1.5:** `FORCE ROW LEVEL SECURITY` on those same Phase 1 tables; `vendors_select` staff/admin-only; payment ledger RPCs.  
**Phase 2 addresses:** `Applications` FORCE RLS + policies; account approval RPCs.  
**LGA-19:** `Applications` admin-only (not maintenance); landlords read-only on Properties + MaintenanceRequests UPDATE.  
**Intentionally deferred:** `inquiries` (website service-role only).

Also pre-Phase 1: core tables (`Landlords`, `Properties`, `Units`, `Tenants`, `Staff`) had **select-only** policies — admin CRUD required additive write policies (included in Phase 1 migration).

## Bootstrap first admin

1. Create Auth user in Supabase Dashboard (or portal signup once enabled) with the intended admin email.
2. Optionally insert a `Staff` row with the same email (for alerts / staff_id later).
3. In SQL Editor (service role):

```sql
select private.assign_admin('you@example.com');
-- assign_admin sets role=admin and account_status=approved
```

4. Sign in on the portal with that user. Role must be `admin`, `maintenance` with `staff_id`, `tenant` with `tenant_id`, or `landlord` with `landlord_id` to pass the app gate.

**Choice documented:** New rows default to `pending`. Helpers + portal gate require `approved`. Bootstrap via `assign_admin` sets `approved`. Phase 2 admins use Users page / `set_account_status` instead of raw SQL for day-to-day approval.
